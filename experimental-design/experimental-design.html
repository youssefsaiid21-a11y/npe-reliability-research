Run in four stages

Use the authors’ GitHub simulator. Start from the Rahmandad/Akhavan repository: its Vensim models, simulation wrapper, original preprocessing and compatible checkpoints. Preserve that baseline and alter only the chosen mechanism in separate model copies. Compiled models need editable source for structural changes; verify the Vensim runtime on this Mac. The simulator has not been run for this design.

Suggested engineering order: Random Walk → Generalized Bass → SEIRb, subject to source availability.

1. Verify the baseline

Match simulator and checkpoint versions. Check equations, priors, grids, noise, preprocessing and numerical behavior.

2. Run a small pilot

50 paired dataset IDs per model, across all four conditions. Measure failures, stability and actual runtime.

3. Freeze and run

Choose a fixed main sample size from the pilot. Freeze settings before generating independent main-test data.

4. Explain the failures

Compare coverage, width and recovery. Add predictive and reference analyses on prespecified subsets.

A dataset ID is one independent parameter draw and random-stream bundle, reused across the four conditions. More posterior draws do not replace independent dataset IDs.

How the main sample size is chosen

The frozen allocation rule uses conservative pilot bounds for common success and paired coverage discordance. It targets an approximate ±3 percentage-point adjusted interval half-width for the three primary largest-departure contrasts.

Use a minimum of 1,000 and a cap of 3,000 IDs per model. If the required count exceeds the cap, declare precision-limited inference before the main run and report the achieved uncertainty. This is a precision target, not guaranteed power.

A material change to the simulator, intervention, checkpoint or sampling rules requires a new allocation pilot. The 600-dataset pilot total assumes one unchanged candidate per model.

What we measure

  • Truth coverage: how often the 95% interval contains the generating parameter.
  • Interval width: uncertainty relative to the original prior range.
  • Recovery error: parameter-wise bias and RMSE.
  • Failures: invalid simulation, preprocessing, inference or reference fits.
  • Secondary diagnostics: predictive adequacy, compensation in other parameters, and reference-posterior agreement.

Keep parameters separate. Narrower intervals alone do not demonstrate better inference.

Where we save compute

  • One misspecification axis and one frozen estimator per model.
  • A shared baseline and paired conditions for each dataset ID.
  • Disjoint pilot and main data; no outcome-dependent stopping.
  • Cache simulations, seeds, checkpoint hashes and per-ID results.
  • Keep expensive predictive and reference work on small subsets.
  • Benchmark actual costs first; use two CPU threads by default.

No large architecture × training-size × noise-type factorial in the core study.

Failed cases stay visible. The primary paired coverage contrast uses IDs that succeed in all four conditions, so it describes that selected population. Always co-report failures and the all-ID probability of both successful inference and truth coverage.

Before execution: resolve the source and baseline checks

Model/checkpoint versions, parameter mappings, observation grids, noise laws and numerical behavior still need verification. The intervention at its baseline setting must reproduce the source model.

Interpretation: use SBC for matched-model validation. Under misspecification, report robustness and truth coverage. An exact posterior under the wrong model can also miss the generating truth; a validated same-model reference is needed to isolate neural approximation error.

The independent reviewer found no unresolved material design flaws after three rounds. That is a design assessment, not evidence that the experiment has run or that these prerequisites have passed.
